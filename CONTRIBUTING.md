# Contributing

Read the [development guide](handbook/development.md) and [architecture](handbook/architecture.md) before changing workflow behavior. Use synthetic data in issues, tests, and screenshots. Report security concerns through [SECURITY.md](SECURITY.md).

Explain the problem and the resulting behavior in a pull request. Include relevant test results and disclose any behavior the tests do not cover. Keep changes to permissions, process state, and persistence together with their regression tests.

Do not commit `.env`, databases, private research, proprietary reference documents, or source screenshots. The existing ignored `docs/` and `research/` directories are deliberately excluded from publication. Public documentation belongs in `handbook/`.
